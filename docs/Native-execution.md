后续交付顺序：mouse、wheel、键盘/文本有界资格完成后，明确执行推进与等待契约、观察与限额资格、旧启动保护逐项终态。上述清单全部获得实现或明确终态及相应证据之前，OB-021 保持未关闭。

`Input.setIgnoreInputEvents` 的当前边界是 session ownership 与 target-effective OR：true 添加调用 session contribution，false 只移除调用 session；导航保留，detach 和 target teardown 清理，新 session 默认 false，不同 target 隔离。有效 ignore 的 mouse/wheel/key 在参数校验后返回空成功，不进入 Page/V8、input navigation 或 command-driven screencast sampling；`Input.insertText` 不受该开关影响。no-render 只覆盖状态/参数控制面，未取得实际坐标或键盘执行资格。paired 工具保留完整原始事件，但恢复阶段不以 click synthesis、legacy `which`、非 control target value 或 coordinate-event caret timing 作为本 gate 的通过条件；这些仍是独立 mouse parity 工作。

contenteditable 的当前边界不是通用 rich editing：只有 `Input.insertText` 与带 text 的 key event、focused editing host、同一 Text 节点 range 才进入 native edit。`beforeinput.getTargetRanges()` 返回原 selection 的 StaticRange；取消、focus 转移或 handler 把 selection 移出原 host 后不修改 DOM。false island 只接收 trusted `beforeinput`。唯一已资格的空文本结构删除要求 direct `span`、唯一 Text child 和左右 Text siblings；其余空字符串整节点结构删除形状在分发 `beforeinput` 前失败。原生删除的 MutationObserver record 按各 observer options 独立创建并在 `input` 后 microtask 交付；公开 DOM getter/query 覆盖不能重入编辑。Backspace/Delete/Enter 与跨节点 range 明确 unsupported；段落拆分、IME/composition 和 grapheme/word editing 保持未资格化。

原始采集数据与工具日志完整保存，不脱敏、不删字段。产品响应 body 的容量失败与工具证据采集不是同一契约，不应通过静默删减原始证据来满足产品限额。

MCP 资源观察投影切片：`NetworkEvent::phase` 在共享 browser 层区分 started、redirect、completed、failed；`browser_network_requests` 改为 pretty JSON 的 `events` 数组，空记录仍返回同一结构。此输出格式有意替换旧文本行。投影保留当前事件的全部字段、原始 header bytes 和关联 ID，不消费事件或响应正文。它只表示 active Page buffer：导航替换 static 记录但 scripted 记录可以保留，上游 JS/Worker 队列超过 4096 条仍丢弃最旧记录。未因此完成 persistent history、queue overflow、请求正文保留或 CDP 多 session 观察资格。

Passive callback ownership 切片：`CallbackRegistry` 的 request/response observer 使用短时 mutex 和 copy-on-write immutable `Arc` snapshot，add/remove 不再因 `try_write` 竞争返回虚假成功或 false-not-found。dispatch 复制 snapshot 后释放 mutex，再按登记顺序传递原始 `RequestInfo`/`Response`；回调内的注册或移除从下一条 observation 生效。移除 tuple 在 guard 作用域外析构，callback capture 可重入同一 registry。公开签名、ID 和数据对象未改变。该契约覆盖 Page、iframe 和 Dedicated Worker 共用的 passive callbacks，但不隔离 callback panic，也不解决 CDP `Network.enable` 的 per-session 订阅/fanout、上游 4096 oldest-drop、持久 observation history 或请求正文保留。

CDP multi-session Network ownership 切片：`Network.enable` 只订阅调用方对应的有效 Page session；事件在产生时 fanout 给当时已启用的 sessions，请求开始时的订阅快照单独决定该 requestId、redirect body alias 与 Document loader alias 的正文可见性。晚启用 session 可以收到启用后的 response/terminal，但不会取得启用前开始请求的 body；disable、detach、Page close 与 connection close 只清理对应 session，重启用不会恢复旧 body 权限。Fetch pause owner 与 Network subscribers 独立，Fetch-only owner 不接收 Network 事件；标准 Network body 查询使用 `fetch-N`/loader requestId，不能以 `intercept-N` 越过边界。sessionless enable/disable 是兼容 no-op，不会清空共享 body store。body-store-wide failure 以每 session 单一 bounded capability 表示，且不会授权读取仍存在的 retained body。Chrome 152 与 Obscura 官方 Playwright 1.60.0 双 session 原始探针确认共享 ID、fanout、晚订阅、disable/re-enable 和独立正文权限；事件、headers、raw bytes 与 body 完整保留。尚未完成上游 JS/Worker 4096 oldest-drop、持久 history、请求正文、Page 总 body 预算与 Chrome per-agent 参数对齐、Fetch stream 共享消费及普通非拦截资源 start emission 架构。

后续 Fetch response stream 切片已完成上述共享消费边界：canonical response slot 的 Fetch whole-body get 与一次 stream take 互斥，但普通 Network/Page 和 persistent-history 读取继续共享 immutable raw backing；alias 不能二次 take。Fetch IO handle 是 target-scoped，同 target sibling session 可顺序读取或关闭，其他 target 拒绝；disable、导航和 body-store clear 保留，last detach、target/Page close、context/connection teardown 回收。Fulfill replacement 更新 canonical generation，不改变已打开 stream 的旧 generation。长度、IO admission 和 Fetch access 转换在同一 store guard 内完成，并在 commit 时校验长度；容量失败不消费正文。PDF 等非 Fetch IO 保持 exact-session 生命周期。Chrome 152 原始探针与本地回归覆盖这些边界，所有 raw body、headers 和协议字段完整保留。

CDP transport 三阶段边界：inbound `ServerMessage` 每连接保留 1024 条、128 MiB UTF-8 text，单消息 64 MiB、单 WebSocket frame 16 MiB；reservation 从 admission 持续到命令执行结束，并在 navigation deferred 时继续保留。`CdpContext.pending_events` 单独限制 1024 条、128 MiB 完整 event envelope 序列化 UTF-8 bytes 和 80 MiB 单事件；无分配 counting writer 计数，批量 admission 全有或全无，失败立即封闭同一连接，既有 accepted events 也不会部分发送。outbound 保留 1024 条、128 MiB、80 MiB 单消息，reservation 延续至 socket send 完成，单次写 deadline 为 10 秒。三阶段 count/bytes/single-message overflow、writer I/O、writer timeout、unsupported binary WebSocket message 和 connection shutdown 首次原因 sticky close，后续命令停止排队；服务不会靠静默丢弃、截断或脱敏维持连接。合法 `Browser.close` 先封闭新 outbound，再以 10 秒总预算尝试 flush 已接受 outbound envelope；pending 不共享 outbound reservation，也不扩展该 flush 契约。

这些限制是三个独立阶段的逻辑 payload 预算，不是总 RSS 上限，也不能合并宣称只有 128 MiB。它们不覆盖 WebSocket text 转为 `String` 前后的瞬时副本、`String`/`Value` capacity、序列化临时分配、channel/Tungstenite/TCP 开销、响应正文、上游 JS/Worker console/network/binding observation 队列或 V8/DOM/render 内存。无效 CDP 的日志保留完整原始 text，不再生成截断 preview；正常 pending event 转发与直接 serde 序列化逐字节一致。Host/Origin/Bearer 只属于控制面 admission，不改变页面/CDP 的完整原始 header/body 观察；任意同步 V8 执行期间的立即断连仍未覆盖。
